# IP 白名单守卫

本页描述 **0.4.4 / versionCode 9**。进程内网络守卫最初在 0.3.0 加入；历史验收保留在对应版本报告。最终 APK 已安装到 Android 16 / arm64 设备并核对摘要，两次冷启动均验证严格美国配置和空名单阻断。受信美国出口尚未提供，当前策略保持离线。

普通 IP 守卫与环境覆盖总开关、环境原生覆盖开关独立，只作用于目标 Claude 进程。显式开启 `privacy_us_only` 后，必需保护统一强制启用；目标版本不匹配会停止目标进程。

## 配置

| 项目 | 普通模式 | 仅美国策略 |
| --- | --- | --- |
| `privacy_us_only` | 未开启 | 用户显式开启 |
| `ip_guard_enabled` | 默认关闭 | 强制开启 |
| `ip_guard_cidrs` | 默认空 | 保留明确配置；空名单拒绝并且不探测 |
| `ip_guard_probe_url` | 默认 `https://claude.ai/cdn-cgi/trace` | 固定 `https://www.cloudflare.com/cdn-cgi/trace` |
| `ip_guard_interval` | 默认 3 秒，可设 1–5 秒 | 保留更短间隔，最长 3 秒 |
| 国家判定 | 不要求国家字段 | 响应须有唯一有效 `loc=US` |

白名单支持 IPv4／IPv6 单个地址及 CIDR，多条用空白、逗号或分号分隔，最多 128 条，支持整行 `#` 注释。地址按字节匹配，两个传输地址族分别授权；IPv4 映射 IPv6 地址按 IPv4 处理，不接受域名和带接口作用域的 IPv6。

保存后完全重启 Claude 加载配置。重复应用预设保留已有身份和 IP 守卫规则；普通预设应用到现有美国策略时继续保持该策略。改变必需保护前须明确关闭仅美国策略。配置使用原子私有快照并检查保存基线，旧 legacy、旧恢复状态或仍存活的旧界面不能覆盖更新的策略；读取损坏或桥接发布失败明确报错。编辑与发布需要可靠的框架桥接。

**空名单、探测失败、歧义响应、超时、地址不匹配、国家条件不满足均拒绝放行。** 不自动将探测得到的地址加入白名单，不提供自动放宽 CIDR 的兜底。

## 探测与许可

`IpGuard.java` 从 Claude 进程发起 HTTPS 探测，使探测遵循该进程的默认网络环境。TLS 使用独立上下文和空客户端密钥管理器，执行系统信任与 HTTPS 主机名校验；不复制应用 Cookie、认证头、客户端密钥，不跟随 HTTP 重定向，不把账号、设备 ID 或白名单作为请求参数。

仅美国预设在向 Claude 域名发起业务连接前，使用 Cloudflare 独立端点检查。探测服务会看到该请求的出口地址；模块日志不打印该地址。空名单直接拒绝，省去无助于放行的预检。

普通模式支持纯 IP、严格 `{"ip":"地址"}` 或 trace 响应。仅美国 trace 必须各有唯一、合法的 `ip` 和 `loc`；重复同值也拒绝，`IP`／`Loc` 等保留字段大小写歧义拒绝。国家值必须是两位大写并且恰为 `US`。IP 解析只核验字面量，准入继续要求明确 CIDR 与地址族条件。无关 trace 字段不要求全局唯一。纯地址响应缺少国家证据时拒绝。响应体上限 4 KiB、头部上限 8 KiB，拒绝压缩、歧义报文、非 200 状态及挑战页面。

`loc` 是本次请求的地区判定，`colo` 是处理请求的 Cloudflare 数据中心代码。美国机房代码不参与国家准入。Cloudflare 官方说明访问者位置依据访问者 IP 判定，IPv4 与 IPv6 也可能走不同路径。[连接验证](https://developers.cloudflare.com/privacy-proxy/get-started/) [地理路由说明](https://developers.cloudflare.com/support/troubleshooting/general-troubleshooting/geographic-traffic-routing/)

默认网络或 VPN／TUN 路由适用于此设计。系统属性或默认代理选择器配置显式 HTTP／SOCKS 客户端代理时，守卫拒绝许可，避免将原始 TLS 探测和客户端代理请求混用。

每个传输地址族独立探测，回显地址族必须相符；无法确认一致的 NAT64／转换情形拒绝放行。网络回调收到变化时同步撤销许可，提交结果前检查网络标识与代次，丢弃旧网络结果。探测结果具有 5 秒观察时效；原生授予许可前用单调时钟再次检查，迟到结果不续期。

许可长度为 `min(10 秒, 检查间隔 × 2 + 4 秒)`。Java 入口检查许可，原生使用 `CLOCK_BOOTTIME` 计算期限。后台线程约每 100 ms 检查到期，撤销时固定进程 Internet socket 的描述符身份并执行 `shutdown`，使已有连接池失效。无法安全枚举或固定描述符时停止进程。

探测豁免限制于私有探测线程及其已核验的 socket 身份。文件描述符关闭后被复用，不继承旧豁免。普通应用请求不获得该例外。

## 代码位置

| 文件 | 责任 |
| --- | --- |
| `IpAllowlist.java` | 字面量解析、CIDR 匹配与映射地址规范化 |
| `ProbeResponse.java` | HTTPS 端点、代理、有界 HTTP、IP 与国家响应校验 |
| `IpGuard.java` | 网络代次、独立探测、Java DNS／socket 入口、原生许可提交 |
| `cpp/ip_guard.cpp` | connect／send／sendto／sendmsg／sendmmsg／getaddrinfo，以及 write／writev／sendfile／sendfile64／splice 与到期撤销 |
| `UsPrivacyPolicy.java` | 仅美国配置的必需条件、固定端点及信任保留 |
| `EnvironmentHook.java` | 加载守卫与目标进程保护 |

必需防护符号共 11 个；当 `sendfile` 与 `sendfile64` 解析到同一地址时仅安装一次，因此符号数与独立 patch 数分别统计。

守卫开启时，由守卫统一安装 7 个网络观察入口，审计复用同一元数据通道，不再重复 hook write／writev。暂停审计不会关闭守卫。sendfile／sendfile64／splice 提供防护，本轮没有为它们扩展审计事件类型；防护入口数不能替代观察覆盖数。

## 网络审计与阻断规则

审计面板中的“非对话网络”只改变 `AuditLog.snapshot(...)` 的显示筛选，既不修改白名单，也不安装阻断规则。审计用来解释已覆盖请求发生了什么；实际准入由下列代码路径执行。

| 机制 | 实际作用 | 边界 |
| --- | --- | --- |
| Sift 阻断 | 严格策略强制 `block_sift`，在已适配的采集、入队和派发入口前停止 | 依赖目标版本与已定位入口 |
| 遥测主机规则 | 必需 `TELEMETRY_HOSTS` 与用户 `blocked_hosts` 合并，DNS 路径拒绝清单内 Sentry／Datadog／Firebase 等域名 | 同域 API 请求、未知域名或直接使用 IP 需要其他约束 |
| IP 守卫 | 按 US、明确 CIDR、地址族、网络状态和有效期准入；当前空名单拒绝 | 单次探测、进程 hook 与已覆盖路径的范围不变 |

元数据包含目的地、请求路径、结果、耗时和可观察字节统计；模块不读取完整 TLS 正文，也不按每份明文负载判断是否敏感。无法据此证明所有隐私字段均被识别，或保证服务端不会对账号采取限制。未覆盖的原生直连、直接 syscall、未知 SDK／版本、同域遥测以及账户历史分别保留为边界。

恢复联网前必须确认受信美国出口，并验证必要请求链路及所需系统路由约束；本轮没有为了展示在线功能临时放行。分析仅使用脱敏汇总，不上传原始数据包或请求正文。

## 使用条件与边界

当前没有已验证的受信美国出口，系统 always-on VPN 和非 VPN 连接阻断也未配置。要恢复联网，需要明确批准的美国出口及 IP／CIDR，并完成该用户或工作资料范围内的实际路由和故障验收。此配置本身不建立 VPN。

进程 hook 通过轮询、网络回调和短期许可工作；无回调的出口变化存在发现窗口。直接系统调用、其他 UID 代发、注入前活动和未覆盖入口需要对应的系统限制。已经发送的数据无法撤回。

按域名、应用或协议分流时，不同目标可能采用不同出口。单次探测描述该次请求；全量路径需要系统配置和实际验证。可配合 [Android VPN 始终开启与非 VPN 连接阻断](https://developer.android.com/develop/connectivity/vpn)，覆盖 IPv4 和 IPv6 并核对应用排除规则。

Unix IPC 保持可用。账户历史、输入正文和附件内容仍由各自的授权与数据处理流程决定，地区字段覆盖不改写服务器保存的信息。在线放行、真实出口切换、VPN 掉线与全路径隔离未作为本轮通过项。
