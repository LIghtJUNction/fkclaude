# IP 白名单守卫

0.3.0 新增进程内网络守卫。它与环境覆盖总开关、环境原生覆盖开关独立；定向环境覆盖遇到未知 Claude 版本时，守卫仍可安装。它只作用于目标 Claude 进程，不会断开全手机网络。

## 配置

| 项目 | 默认值与行为 |
| --- | --- |
| 独立开关 `ip_guard_enabled` | 关闭；明确配置白名单后再开启 |
| 白名单 `ip_guard_cidrs` | 空；支持 IPv4／IPv6 单个地址及 CIDR，多条用空白、逗号或分号分隔，最多 128 条；支持整行 `#` 注释 |
| 回显地址 `ip_guard_probe_url` | `https://claude.ai/cdn-cgi/trace`；必须为 HTTPS、默认端口或 443，无账号信息、片段或控制字符 |
| 检查间隔 `ip_guard_interval` | 3 秒，可设 1–5 秒 |

名单按地址字节匹配，IPv4 与 IPv6 分开授权；IPv4 映射 IPv6 地址按 IPv4 处理。不接受域名和带接口作用域的 IPv6。保存后完全重启 Claude 才加载配置；重复应用预设会保留这些值。

**开启后空名单、探测失败、返回格式错误、超时、地址不匹配均不放行。** 未配置时不会自动把当前出口加入白名单。配置无法读取、必要权限缺失或原生拦截无法安装会停止 Claude 进程，避免以失效守卫继续运行。

## 探测与许可

`IpGuard.java` 在 Claude 进程自身发起匿名 HTTPS 探测，避免模块 UID 与 Claude UID 受到不同 VPN 规则影响。探测线程有私有豁免，普通应用请求没有该豁免。TLS 使用独立上下文和空客户端密钥管理器，使用系统信任校验及 HTTPS 主机名校验；不接入应用的 Cookie、认证头或 HTTP 重定向。不会把账号、设备 ID 或白名单作为请求参数，也不在模块日志打印出口 IP。

默认端点是 [Cloudflare 的 `/cdn-cgi/` 调试接口](https://developers.cloudflare.com/fundamentals/reference/cdn-cgi-endpoint/)，不是 Anthropic 承诺长期提供的 IP API。端点不可用、挑战页面或状态非 200 都会阻断。也可换为可信的 HTTPS 服务，支持纯 IP、严格的 `{"ip":"地址"}`，或含唯一 `ip=` 字段的 trace 文本。响应体上限 4 KiB、头部 8 KiB，拒绝压缩及歧义报文。

仅支持默认网络路由或 VPN／TUN 路由。若系统属性或默认代理选择器配置了显式 HTTP／SOCKS 代理，守卫拒绝授予许可；原始 TLS 探测无法证明这种客户端代理的出口与应用请求一致。

每个传输地址族独立探测，回显地址族必须相符；严格拒绝无法证明一致的 NAT64／转换情形。网络回调收到变化时同步撤销许可并重新检查。提交结果前检查网络标识和代次，丢弃旧网络结果。每个探测结果仅有 5 秒观察时效，原生最终授予许可时再次用单调时钟检查；暂停、排队或迟到结果不会重新续期。DNS 解析可能超出 socket 的超时窗口，但过期结果无法放行。

许可长度为 `min(10 秒, 检查间隔 × 2 + 4 秒)`。Java 入口检查许可，原生使用 `CLOCK_BOOTTIME` 计算期限。原生后台线程每约 100 ms 检查到期，撤销时枚举并固定进程 socket 的文件描述，再执行 `shutdown`，使已有连接池失效。枚举／固定描述符失败时停止进程，不默默保留已建立连接。

## 代码位置

| 文件 | 责任 |
| --- | --- |
| `IpAllowlist.java` | 纯字面量解析、CIDR 匹配及映射地址规范化 |
| `ProbeResponse.java` | URL、代理和有界 HTTP／IP 响应校验 |
| `IpGuard.java` | 网络代次、匿名探测、Java DNS／socket 入口、原生许可提交 |
| `cpp/ip_guard.cpp` | `connect`、`send`、`sendto`、`sendmsg`、`sendmmsg`、`getaddrinfo` 六个原生入口与到期撤销 |
| `EnvironmentHook.java` | 先加载守卫，再安装可选环境覆盖 |

## 边界与验收状态

- 这是轮询与网络回调驱动的进程 Hook，不是系统 UID 防火墙；出口变化没有回调时存在发现窗口，不能保证异常出现的瞬间零流量。阻断前已经发出的数据无法撤回。
- 直接系统调用、其他 UID 代发、注入前流量、未覆盖入口有边界；阻断后已有普通 Internet socket 会被关闭，但不能据此声称内核级全流量隔离。
- 分域／分应用／按协议代理可能让回显域名与 API 请求走不同路径；一个回显不能证明所有目的地的出口。不要据此推断账号安全或支持地区资格。
- 原生不阻断 Unix IPC。回显例外限定于探测线程及该线程建立、身份校验过的描述符；描述符关闭重用不会继承例外。
- 当前已做主机模拟 Hook、真实本机回环 socket 撤销及 Android 编译／静态检查。尚未在手机上验证新守卫或切换实际公网出口；手机原有 0.2.1 安装不包含此功能。

需要更强的网络边界时，可结合系统 UID 防火墙或 [Android VPN 的始终开启／无 VPN 时阻断功能](https://developer.android.com/develop/connectivity/vpn)，并按实际路由验证。上述限制不会因伪造环境字段而消失。
