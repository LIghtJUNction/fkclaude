## 1. 问题与修复

| 问题 | 本轮处理 | 验证 |
| --- | --- | --- |
| 中断写入留下无 LF 尾行，后续事件可能拼到旧片段后 | 追加前检查末字节，必要时补 LF，保留原有全部字节 | 5 项尾行回归；真机旧片段独立保留，其后 635 条事件有效 |
| 复制事件与读取状态／计数分属不同时间，导出可能错配 | 同一加锁采样阶段捕获事件、状态和计数；生成不可变快照，序列化只读快照 | 4 项快照回归，含并发清空；两份真实导出计数匹配 |
| 进程重建时历史未加载，结果回调可能过早导出或截断目标 | 未就绪时拒绝快照；后台最多等待 5 秒，得到快照字节后才以 `wt` 打开目标 | 未就绪／重试回归；新进程实际恢复并保存完整历史 |
| 全局导出标志缺少 Activity 归属，重建后可能丢失请求 | 按 Activity 保存 token／requestCode，恢复小型请求状态；配置替换转移归属，在 `onCreate` 前准备结果 hook | 7 项请求状态回归；取消后重开、进程回收后完成同一请求 |
| 慢文件提供器会占用列表／清空线程 | 独立单线程导出执行器，等待队列容量 1 | 源码与正常设备交互；本轮未人工注入慢提供器 |
| 文件选择器可能迁移显示器 | 启动时提示当前有效显示 ID | 尽力提示；本机正常保存与恢复保存已完成 |
| CLI 漏报完整行边界截断 | 每个导出块核对 `retained` 与有效物理事件行数，计数在全局去重和筛选前 | 25 项 Python 回归；923 条和 1,000 条真实导出均匹配 |
| 损坏 gzip 导致整个汇总中断 | 捕获 `zlib.error`，记录文件错误并继续后续输入 | 损坏压缩输入后仍读取有效文件的回归通过 |

补 LF 只恢复记录间的边界，不补造旧 JSON 内容。损坏片段保留并可见，后续新事件获得独立行。导出快照则固定了事件与元信息，避免序列化过程中读取变化中的现场状态。

## 4. 最终 APK 设备实验

设备为 **PHK110 / Android 16**，目标应用版本为 **1.261112.18 / 26111218**，使用独立虚拟显示器。各实验窗口分开记录，事件数不跨阶段相加为上传量。

### 4.1 真实中断尾行恢复

在独立测试日志末尾人工追加半截 JSON 后冷启动，旧片段保持原字节并独立成行。其后产生 **635 条有效事件、0 条坏行**，包含新 `audit_started`，observer_error 为 0。

“0 条坏行”只描述注入片段之后的新事件。人工损坏片段自身仍保留，状态页明确显示 **无效历史 1、磁盘错误 0**。清空并重新启动后，新进程无效历史计数恢复为 0。这个实验同时验证续写分隔与损坏可见性。

### 4.2 开启记录期间清空

| 观察 | 结果 |
| --- | --- |
| 清空后约 2 秒 | 9 条事件，其中 2 条 native；`native_reset_applied` |
| 后续样本 | 53 条事件，其中 14 条 native |
| 清空前时间戳事件回流 | 0 |
| observer_error | 0 |

清空后继续产生新事件，旧时间窗口的事件未回流。两个样本是相继取得的状态，不累计成 62 条事件。

### 4.3 真实软件键盘与搜索

点击输入框后实际显示 IME，输入 `datadog` 得到对应查询结果。面板随键盘缩小，搜索、筛选、操作区和列表仍可见；键盘可收起，中文输入模式已恢复。

本段使用最终 0.4.3 APK。此前 0.4.2 的 `--display-ime-policy=local` 结果只是测试环境基线。

### 4.4 正常 SAF 保存与取消重试

正常保存生成 **513,333 字节** NDJSON，共 **924 行**：1 行 manifest 与 **923 条事件**，`retained=923`。

取消选择器后立即重新发起导出，选择器成功重开；该重开请求随后用于下一节的进程恢复实验并完成保存。因此取消后的完整重试保存也得到覆盖。

### 4.5 选择器等待期间的进程回收与恢复

将等待中的文件选择器任务退到后台，打开模块界面但未修改设置；确认 Claude Activity 进入 **STOPPED**，再执行 `am kill`。确认旧进程消失后回到原文件选择器保存，核对接收结果的新进程 PID 已变化，**同一导出请求在新进程成功完成**。

恢复保存生成 **568,104 字节** NDJSON，共 **1,001 行**：1 行 manifest 与 **1,000 条事件**，`retained=1000`。证据为 `saf-process-recovered.json` 与 `process-recovery-result.json`。

| manifest `retained` | 923 | 1,000 |

| `history_loaded` | true | true |
